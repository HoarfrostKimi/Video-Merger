# Video Merger · 视频合并工具

一款基于 **Electron** 的桌面应用，专为**直播录播用户**设计：自动扫描 FLV 分段、按场次智能分组、一键合并成完整 MP4，还能定时自动合并、自动投稿到 B 站。

![Electron](https://img.shields.io/badge/Electron-33-blue) ![React](https://img.shields.io/badge/React-18-61dafb) ![TypeScript](https://img.shields.io/badge/TypeScript-5-3178c6) ![License](https://img.shields.io/badge/License-MIT-green)

---

## 这个东西解决什么问题

用录播姬、BililiveRecorder 之类的软件录直播，拿到的往往是一堆几分钟到几十分钟的 FLV 分段文件。手动拼？既费时间又容易乱序。

这个工具把整件事变成一句话：**扫一遍，选一下，合起来。**

```
BililiveRecorder 录制目录
├── 2026-10-29 19-20-44-000 某主播的直播.flv
├── 2026-10-29 19-25-12-000 某主播的直播.flv
├── 2026-10-29 19-31-03-000 某主播的直播.flv
└── ...
                    ↓  扫描 + 智能分组
        「2026-10-29 某主播的直播」一个分组
                    ↓  FFmpeg stream copy（不重编码，保留原画质）
        2026-10-29_某主播的直播_192044.mp4
```

## 功能一览

### 合并

| 功能 | 说明 |
|---|---|
| **文件夹扫描** | 选择目录后递归扫描所有视频文件，支持两个目录同时扫描 |
| **智能分组** | 按文件名里的日期 + 标题归组，自动识别同一场直播的分段（含 `_PART00X` 后缀） |
| **不压缩合并** | FFmpeg `stream copy`，不重新编码，速度快且画质无损 |
| **批量并行** | 多个分组同时合并，并发数可调（上限 4） |
| **场次精确识别** | 同一天多场直播不会互相误判；已合并的场次自动标记，不会重复处理 |

### 自动化

| 功能 | 说明 |
|---|---|
| **定时自动合并** | 每天到设定时间，自动合并**昨天**录制的场次 |
| **合并后自动投稿** | 定时合并完成后自动打开 B 站投稿页，由浏览器插件接着上传 |
| **自动清理旧文件** | 超过 N 天的分段与合并产物自动移到回收站（可从回收站找回） |
| **合并后自动打开** | 自动弹出输出目录 / 投稿页面 |

### 远程与辅助

| 功能 | 说明 |
|---|---|
| **手机控制面板** | 同一局域网内用手机浏览器查看进度、发起合并（带密码） |
| **B 站投稿助手** | 配套浏览器扩展，自动填标题、选创作声明、传封面、提交 |
| **排除分组** | 临时隐藏不想合并的分组，状态自动保存 |
| **后台运行** | 关闭窗口最小化到托盘，定时任务继续跑 |
| **深色模式** | 跟随系统或手动切换 |

## 安装

### 方式一：直接装（推荐普通用户）

1. 到 [Releases](https://github.com/HoarfrostKimi/Video-Merger/releases) 下载最新的 `video-merger-x.x.x-setup.exe`
2. 双击安装，按向导走完
3. 从开始菜单或桌面图标启动

> 安装包已内置 Chromium 与 FFmpeg，**不需要另外装这两个**。

### 方式二：从源码跑（开发者）

```bash
git clone https://github.com/HoarfrostKimi/Video-Merger.git
cd Video-Merger
npm install
npm run dev          # 开发模式（热更新）
```

打包安装程序：

```bash
npm run dist         # 产物在 dist/ 目录
```

macOS / Linux 可以用 `./build.sh`，Windows 用 `build.bat` 一键打包。

### 系统要求

- Windows 10 / 11（主要支持；macOS、Linux 可自行构建）
- 磁盘空间 ≥ 500MB（含内置 Chromium + FFmpeg）
- 内存建议 4GB 以上

## 怎么用：完整流程

### 第一步：选文件夹

启动后点「选择输入文件夹」，选中你录播软件的输出目录。

如果分段分散在两个目录，第二个目录也可以一起选（会合并扫描结果）。

再选一个「输出文件夹」——合并后的 MP4 放这里，**建议选在剩余空间充足的盘**。

### 第二步：扫描

点「扫描」。工具会递归读取所有视频文件，按文件名解析出「日期 + 时间 + 标题」，把同一场直播的分段归到一起。

扫描结果是一张表，每行一个分组，显示分段数量、总大小、时间范围。

> 文件名格式要求：`YYYY-MM-DD HH-MM-SS-xxx 标题.flv`。这是 BililiveRecorder 和大多数录播工具的默认命名，如果你的命名不同，可能归组不准。

### 第三步：选分组并合并

勾选要合并的分组（可以多选），点「开始合并」。

- 默认走 **stream copy**，速度取决于磁盘读写，几乎不重新编码
- 并发数在设置里调，默认 3。机器内存小时建议调到 1–2
- 合并过程中能看到每个分组的实时进度

合并完成后：
- 成功的分组会从列表移除（已合并标记）
- 输出文件名格式：`标题_日期_时分秒.mp4`，带开始时间是为了避免同一天多场直播重名

### 第四步：投稿到 B 站（可选）

这一步需要配合浏览器扩展，分两半：

**① 安装扩展**

```bash
cd bilibili-extension
npm install
npm run build
```

然后打开你的浏览器：

- **Chrome / Edge**：地址栏输入 `chrome://extensions`（Edge 是 `edge://extensions`）
- 右上角打开「开发者模式」
- 点「加载已解压的扩展程序」，选择 `bilibili-extension` 整个文件夹
- 加载后，插件面板标题旁边会显示版本号，说明装好了

> 扩展支持所有 Chromium 内核浏览器（Chrome、Edge、豆包浏览器、QQ 浏览器等）。

**② 在应用里投稿**

勾选「已合并文件」列表里的视频，点「投稿」。

应用会：

1. 注册本地文件服务（`127.0.0.1` 随机端口）
2. 打开 B 站投稿页，URL 带上待上传文件的地址
3. 扩展读取参数，自动下载文件、填标题、选「创作声明」、设可见范围、截视频帧当封面、点投稿

你只需要在浏览器里确认一下，剩下的都自动完成。

> **重要**：投稿期间别最小化浏览器窗口。后台标签页会被浏览器节流，可能导致上传卡住。

### 第五步：定时自动合并（可选）

设置 → 定时合并：

| 设置项 | 说明 |
|---|---|
| 定时自动合并 | 总开关，默认关闭 |
| 合并时间 | 24 小时制，默认 `03:00` |
| 合并后自动投稿 | 开启则合并完自动打开投稿页 |

行为说明：

- 每天到点触发一次，**只合并「昨天」录制的场次**，今天还在录的不会动
- 已合并过的、被你排除的、输出文件已存在的，都会跳过
- 串行执行（一次合一个），夜间无人值守时更稳
- 时间点按 30 秒粒度检查，同一分钟只触发一次，不会重复

> 应用必须保持运行，最小化到托盘也算。完全退出就不会执行。

## 手机端控制

设置 → 远程控制 → 打开「手机控制面板」，设一个密码。

然后在手机浏览器（需和电脑同一 WiFi）打开应用显示的地址，例如：

```
http://192.168.1.100:9820
```

能做的事：查看分组列表、发起合并、看进度、触发投稿、查看运行状态。

> 电脑换 WiFi 后 IP 会变，以应用面板显示的地址为准。

## 主要设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| 合并时间间隔阈值 | 2.5 小时 | 同一场直播的分段最大间隔，超过就视为两场 |
| 并行合并数 | 3 | 上限 4，内存小时调低 |
| 自动打开输出文件夹 | 开 | 合并完成后弹出目录 |
| 合并后自动打开投稿页 | 开 | 配合插件使用 |
| 投稿后自动关闭浏览器 | 关 | 插件回传完成信号后关闭窗口 |
| 后台运行 | 关 | 关闭窗口最小化到托盘 |
| 自动清理旧文件 | 开 | 每 24 小时清理一次 |
| 旧文件保留天数 | 7 天 | 移到回收站，可找回 |
| 定时自动合并 | 关 | 见上一节 |
| 手机控制面板 | 开 | 端口 9820，需设密码 |

配置文件位置：`%APPDATA%\video-merger\config.json`（开发模式在项目内 `user-data/`）。

## 常见问题

**Q：合并很慢 / 卡在某个百分比**

优先看磁盘。stream copy 的瓶颈几乎都在磁盘读写，机械硬盘 + 多个分组并发会明显变慢。把并发数调到 1，或把输入输出放在不同物理磁盘上。

**Q：投稿时提示「请添加创作声明」**

B 站 2026 年把这一项改成必填了。确认扩展是最新版（面板标题带版本号），旧版本不会自动选这一项。

**Q：投稿时提示「请上传首页推荐 4:3 封面」/「个人空间 16:9 封面」**

新版封面要求两个比例各一张。同样，确认扩展是最新版，它会同时填两个比例。

**Q：点了投稿，浏览器没反应**

检查默认浏览器是不是你装了扩展的那个。应用用系统默认浏览器打开投稿页，扩展装在 A 浏览器、默认是 B 浏览器的话，页面打开了但没人接管。

**Q：上传很慢**

上传到 B 站的速度取决于你的**上行带宽**，1GB 大约需要几分钟到十几分钟，这部分应用无法优化。要更快只能减小文件体积。

**Q：定时合并没执行**

三个检查点：① 总开关是否打开 ② 应用是否还在运行（最小化到托盘也算运行）③ 当天是否有「昨天」的场次且未合并过。日志里会打印 `[autoMerge]` 开头的记录。

**Q：改名后的文件不被识别**

分组依赖文件名里的 `YYYY-MM-DD HH-MM-SS-xxx 标题` 格式。改名后可能归到「未知日期」分组。

## 技术栈

| 层级 | 技术 |
|---|---|
| 桌面框架 | Electron 33 |
| 前端 | React 18 + TypeScript 5 |
| 构建 | Vite 5 + electron-vite |
| UI | Ant Design 5 |
| 状态 | Zustand 5 |
| 视频处理 | FFmpeg（内嵌，无需单独安装） |
| 打包 | electron-builder 25（NSIS） |

### 目录结构

```
.
├── src/
│   ├── main/              # 主进程：文件服务、合并调度、定时任务、控制服务
│   ├── preload/           # 预加载脚本（IPC 桥）
│   └── renderer/          # 渲染层：React 界面
├── bilibili-extension/    # B 站投稿助手浏览器扩展（MV3）
└── dist/                  # 打包产物
```

### 开发命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发模式（热更新） |
| `npm run build` | 构建主进程 + 渲染层 |
| `npm run pack` | 打包为免安装目录 |
| `npm run dist` | 打包为 NSIS 安装程序 |
| `npm test` | 运行单元测试 |

扩展相关：

```bash
cd bilibili-extension
npm run build      # 构建 dist/content.js
npm run watch      # 监听模式
```
